# Testpass 个性化 AI 考试通过助手

> 一个按考试督促你的陪练：先问你要应对哪一场、现在什么水平，然后每天只安排最弱的一块，收下你站内做的题和自己交来的卷子，并把实力的变化记下来。

---

## 一、它解决什么问题

备考的人不缺题库，缺的是**今天该做什么**，以及**做完之后有没有变强**。

常见工具的两种失败：

- 只给题，不给顺序。打开就是几百道题，人挑最顺手的做，最弱的一块永远不碰。
- 只记分，不解释。分数涨跌没有依据，错了不知道为什么错，做对了也不知道是不是蒙的。

Testpass 把「安排」和「记账」拆开做：

- **安排**：每天只给一个专项、一个时长、一句话说明为什么是它。做不动可以降档，降到底就今天停手，不假装努力。
- **记账**：站内答题、整卷自交、模拟考卷都折算成同一个分数口径，写进可回放的事件流，随时能重算出「开始时多少、现在多少」。

## 二、一个完整的使用流程

1. 进入首页，选一场考试（操作系统 / 计算机网络 / 数据结构）、现在的水平（刚开始 / 基础能做 / 有的章节会崩 / 在冲高分），填考试日期和目标分。
2. 「今日」给出今天的专项：当前分数最低的知识点，25 分钟，附一条为什么是它的理由。
3. 做不动就点「今天做不动」：时长降到 12 分钟；再点一次，今天不再加任务。隔天没做，下一次收到 18 分钟，仍是同一块。
4. 「模拟」做开放题并交卷，交卷后逐题说明对错，分数跟着改；「对话」可以把卷面拍给 Testpass，或让它按当前专项去公开页面找真题。
5. 「交我做过的」填对题数和错法——如果另一块因此变成最低，今天的专项会当场改过去。
6. 「实力」看到开始时的刻度和之后的升降，以及按当前节奏到考试日大概能到多少分。

## 三、功能清单

| 页面 | 做什么 |
| --- | --- |
| 首页 / 设定 | 选考试、水平、考试日期与目标分；可一键载入一份「练过几天」的演示记录 |
| 今日 | 今日专项、连续天数、目标预测、到期复习卡、站内专项练习；操作系统「页面置换」专项带可交互的置换模拟 |
| 对话 | 文字提问、卷面拍照识别、按专项检索公开真题（只抽取页面上真实出现的题干并给出处）、题库导入 |
| 模拟 | 开放题作答 → 交卷 → 逐题讲评 → 分数变化 |
| 实力 | 起始基线、当前分数、历史升降、薄弱项排序、目标达成预测 |

## 四、算法与规则

### 分数

- 每个知识点一个分数，范围 8–96（`clampScore`）。
- 站内题：做对 +8，做错 −4。
- 完成当日专项：+4。
- 自交整卷：以 60% 正确率为零点，`round((正确率 − 0.6) × 20)`，同一份卷子再交一次增减相同。

### 每日专项（规则可枚举、可解释）

| 编号 | 触发 | 结果 |
| --- | --- | --- |
| `LOWEST_TOPIC` | 默认 | 只安排当前分数最低的知识点，25 分钟 |
| `SKIP_TRIM` | 前一天有未完成的专项 | 下一次 18 分钟，仍是同一块 |
| `SKIP_SHRINK` | 当天点「做不动」 | 12 分钟；再点一次，今天不再加任务 |

界面上那句「为什么是它」可以走大模型生成，但**分数和专项永远由规则决定**——模型挂了，页面仍显示按规则写好的话。

### 能力估计与回放

- 每个知识点除分数外还有 Elo 式的 `rating` 与 `uncertainty`，答对/答错按题目难度更新（初始 1200）。
- 所有答题、交卷、降档、跳过都写成 `attempts` 事件，带稳定 UUID；从事件流可完整重放出 mastery、能力值、连续天数、当日专项和历史升降（`algo_version = score-elo-v1`）。
- 迁移前缺少原始答案的旧记录只保留快照，派生层明确标记来源为「迁移快照」，不伪造原始答题证据。

### 复习与预测

- 复习卡按 ease / interval / repetitions / lapses 排期（SM-2 变体），到期出现在「今日」。
- 设定时填「这场卷子」：题量、难度（偏易/正常/偏难）、各章占比。预测先把各章掌握度按占比加权，再按难度加减，得到「你现在大概几分」；再用最近几天的升降速率给出考试日的区间（节奏的影响最多 ±20 分），区间随练习天数收窄。

## 五、技术架构

```
┌──────────────────────────── 浏览器 ────────────────────────────┐
│ React 19 + Vite 8 + TypeScript + Tailwind 4                    │
│  ├─ 页面：Setup / Today / Talk / Mock / Progress               │
│  ├─ 引擎：score · plan · model(Elo) · replay · forecast        │
│  └─ 记录层：RecordStore（本地缓存 + 待发送队列 + 身份隔离）      │
└───────────────┬───────────────────────────────┬────────────────┘
                │ Supabase JS（匿名登录 + JWT）  │ fetch
                ▼                               ▼
┌──────────────────────────────┐   ┌─────────────────────────────┐
│ Supabase Postgres            │   │ Vercel Functions            │
│  exams / attempts /          │   │  /api/senior  评语·识图·检索 │
│  import_jobs / sources/items │   │  /api/v1/*    题库导入      │
│  RLS：user_id = auth.uid()   │   │  服务端只用 publishable key │
│  save_record_state() 事务函数 │   │  SSRF 防护、体积上限        │
└──────────────────────────────┘   └──────────────┬──────────────┘
                                                  │
                                          DeepSeek（可选）
```

- **前端**：React 19、Vite 8、TypeScript、Tailwind 4、React Router 7；状态用 `useSyncExternalStore` 订阅记录层，写入先落本地再异步同步。
- **数据**：Supabase Postgres + 匿名登录 + 行级权限；`exams.record_state` 存 UI 恢复快照，`record_revision` 做乐观并发。
- **同步**：`save_record_state` 是 `SECURITY INVOKER` 函数，用调用者 JWT、RLS、考试行锁和版本比较，把「快照更新」与「事件追加」放进同一事务；版本不符返回 `PT409`，客户端重读、合并、重试。`attempts` 只插入，冲突 `DO NOTHING`，触发器禁止改删。
- **离线**：失败的动作留在队列里，网络恢复或点「重试同步」后串行发送；身份变化丢弃旧请求的 UI 回写。
- **导入**：`POST /api/v1/imports` 支持公开链接、粘贴 HTML/纯文本、JSON/CSV/Markdown 上传；服务端抓取不带 Cookie/Authorization，私网、链路本地、云元数据地址在发请求前拒绝；登录墙记为 `LOGIN_WALL` 并引导粘贴。
- **AI**：评语、识图、真题检索走 DeepSeek，密钥只在服务端；没有密钥时全部退回规则文案，分数不受影响。

## 六、数据与隐私

- 默认不注册：匿名身份随浏览器数据保存；在「账号」页可以绑邮箱，之后用同一邮箱收登录链接，记录跟着账号走。
- 所有行按 `auth.uid()` 隔离，跨用户不可见；服务端不接受 `service_role` 密钥，也不接受带 `sb_secret_` 的配置。
- 题库导入的请求体若包含 Cookie / Authorization / storage_state 等字段直接 `400` 拒绝，不落库。

## 八、边界（这一版有意不做）

- 每场考试只开放 4 道站内题，用来把错法和分数记实；完整题库是后续收费项。
- 账号只有邮箱一种方式：不做密码，不做第三方登录；不绑邮箱时记录只在那台浏览器里。
- 没有服务端 AI 密钥时，评语退化为规则文案（功能可用，语气变平淡）。
- 题库导入以「题干 + 选项 + 答案」为主，CSV / Markdown 目前只导入题干。

## 十、本地运行

```bash
npm install
npm run dev     # http://127.0.0.1:4731
```

不配 Supabase 也能完整使用，记录存在本机。要体验云端同步与题库导入，复制 `.env.example` 为 `.env`，填入 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISHABLE_KEY`（匿名登录需在 Supabase Dashboard 打开 Anonymous），可选填服务端 `DEEPSEEK_API_KEY`。

数据库迁移在 `supabase/migrations/`，按文件名顺序应用；发布步骤见 [deployment.md](deployment.md)。
